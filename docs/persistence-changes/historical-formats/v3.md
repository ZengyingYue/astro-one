<a id="characteristics"></a>
## Format characteristics

These facts describe the selected checkpoint. The generated tables below preserve the exact field types and optionality.

- `SessionHeader.version` resolves to the literal 3. Logical and physical headers require `isSeeded`; the physical header has no `seedLength`.
- `system/message`, `user/message`, `assistant/message`, and `tool/result` require `surfaceOp`. Replacement endpoints are `startSeq` and `endSeq`; Assistant messages do not carry `sourceEventSeqs`.
- Assistant streams remain embedded in message or attempt events. System prompt text belongs to `system/message`, and PTC dispatch events use `tool/ptc-dispatch-start` and `tool/ptc-dispatch`.

The [V3 codec](../../../packages/session/session-format-v2-to-v3/src/codec.ts) owns canonical event framing and source-event range encoding. The [V2-to-V3 specification](../../../packages/session/session-format-v2-to-v3/README.md#v2-to-v3-specification) defines historical conversion, while its [native V3 admission rules](../../../packages/session/session-format-v2-to-v3/README.md#native-v3-admission) distinguish extension handling from historical source validation.

For a seeded V3 Session, the last `session/end-seed` event carrying `data.inherited: true` identifies the inherited cut by its sequence position. Physical `sourceEventSeqs` may use encoded ranges; the logical schemas retain expanded number arrays.

<a id="verification"></a>
## Verification and limitations

`pnpm run verify-persistence-catalog` passed before `pnpm run verify-persistence-formats --archive 3` created the schema from the current V3 inventory. Archival retains every root and its reachable declared types, preserves root digests and opaque declarations, and removes source line numbers. Earlier format records remain unchanged.

The inventory records declared fields and optionality, not every codec or restoration invariant. External plugin payloads, physical range encoding, and runtime relationships need their owning validators; schema completeness alone does not establish migration safety.

```sh
pnpm run verify-persistence-formats
```

The check validates every format through the current writer, schema completeness, bilingual declarations, and generated tables using only this checkout. It does not replay historical applications. See the [format index](README.md) for maintenance rules and the [current catalog](../../persistence-catalog.md) for today's declarations.
